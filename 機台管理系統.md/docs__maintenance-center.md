# 維修中心

新版以每一筆故障為單位處理；同一台機台的多筆故障，各有自己的負責人、照片、交接與解決狀態。報修不必先建立工程師、站點或流程，也不必操作計時。

## 日常操作

1. 選擇專案，按「快速報修」。輸入機台序號／資產編號及一句問題即可建立；照片選填。既有機台與曾報修識別可再次選用。
2. 清單預設未解決；狀態、負責人／「＋ 指派」與箭頭固定在同一行。點負責人可選多位平台帳號；「我負責」也包含共同處理的第二位以後人員。
3. 在詳情送出處理紀錄，可連續貼圖、多選或拖入附件，每檔50MB。相同檔名也會追加；部分失敗時成功項目保留，重試只處理剩餘檔案。
4. 將重要訊息置頂為「交接重點」。狀態可切待處理、查因中、維修中、等料；解決時必填目前專案分類，之後可重新開啟。
5. 問題儀表板依目前專案的全部故障歷史整理機台與分類，含已解決資料。點排名帶入相同清單篩選；各條件皆可單獨清除或全部清除。

新增專案只必填名稱；負責人、日期與狀態放在選填設定。人員沿用有維修編輯權限的平台帳號，不另維護工程師名單。通知管道依本次決定暫不串接 Teams、LINE 或 Email。

## 原資料保留方式

| 原資料 | 新版的使用方式 |
| --- | --- |
| `test_projects` | 原專案及ID直接沿用，封存專案也可選擇查閱 |
| `test_systems` | 原機台、序號、工程師與其他資料保留；報修可連結原ID |
| `issues` | 原故障ID、描述、處理說明、解決方式及其他原欄位沿用；只增加維修專用欄位 |
| `issue_attachments`、原Storage物件 | 原附件原路徑繼續預覽／下載；新附件追加至各則訊息 |
| `test_progress`、流程與時間紀錄 | 從「舊測試紀錄」唯讀查閱；新版故障動作不重置原進度 |
| `maintenance_messages` | 追加新訊息與操作歷史，操作者及時間由伺服器產生 |

舊 `open` 顯示待處理、`in_progress` 顯示維修中、`resolved`／`closed` 顯示已解決；讀取不回填或改寫原狀態。舊負責人文字保留，重新指派才改為平台帳號並記錄原指派。舊已關閉且未分類的紀錄仍可查閱及指派，不要求先補分類；之後重新解決時才要求分類。

資料庫第一筆遷移在同一交易中擷取所有原故障與附件的ID及完整欄位，再排除新增欄位逐筆核對。任何差異都中止並回滾。核對時有7個專案（4個封存）、132台機台、75筆故障及33個附件；遷移沒有刪除或搬空來源。

## 驗證範圍

- `tests/maintenanceWorkflow.test.mjs`：舊狀態／人名相容、多人與同機分組、URL篩選、含結案的統計；未識別機台不冒充同一台反覆故障。
- `tests/maintenanceWorkflow.postgres.sql`：在正式資料庫交易內測試建立、冪等重試、指派、訊息、交接、解決／重開、併發衝突、原文保留、另一帳號接手、身分限制及封存限制；測試資料全部回滾。
- `tests/maintenanceWorkflow.browser.cjs`：使用實際元件與隔離共享HTTP資料測試兩個帳號、讀取補同步、12張圖（含重複檔名與貼上）、部分失敗重試、原附件預覽、唯讀帳號、封存查閱與僅填名稱建立專案。
- 手機／電腦視窗為390、536、1180、1440px；包括短視窗與VisualViewport縮小的輸入排版。這是瀏覽器模擬，尚未驗證實體iPhone鍵盤與Safari。
- 原有工具與資產沿用；封存專案不再寫入／移除專案資產關聯。公司共用庫仍沿用原有管理流程。

正式網站的兩個真實登入分頁尚未人工對照；後端跨帳號契約及隔離瀏覽器雙帳號流程分別驗證。即時訂閱之外，回到頁面、恢復連線及可見頁面每5秒會補讀，避免訂閱中斷後必須重新整理。
