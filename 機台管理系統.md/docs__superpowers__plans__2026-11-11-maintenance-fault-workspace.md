# 維修中心故障工作區實作

**Goal:** 保留「維修中心」名稱，以可交接的故障紀錄取代計時與逐站操作，完成手機及電腦介面並提交。

**Architecture:** 沿用 `workspace.issues`、專案、平台帳號與既有附件；加入五種維修狀態、多人指派、未登錄機台識別及不可覆寫的訊息／操作紀錄。新增與更新透過受既有維修權限保護的原子 RPC。既有 BOM、AI、工具與資產資料不改。

**Tech stack:** React、TypeScript、既有 Radix 元件、Supabase PostgreSQL／Storage／Realtime。

## 已確認契約

- 一台可有多筆獨立故障；預設目前專案未解決，依機台分組，可切「我負責」。
- 狀態：待處理、查因中、維修中、等料、已解決。未分派依負責人自動判定，不是第六種狀態。
- 新增只需機台序號／名稱與一句問題；圖片選填。未知機台先保存識別，不要求 L10 流程。
- 多位共同負責人使用平台帳號；有維修編輯權限的專案成員皆可協作，不另建工程師名單。
- 訊息與附件追加；操作者與時間由伺服器記錄；可將訊息設為交接重點。
- 處理人可直接結案，但結案必填該專案分類；可重新開啟並保留歷史。
- 手機清單的機台、狀態、負責人／＋指派與箭頭同列；標題與摘要各自一行，列高一致。
- 電腦清單／詳情並排、報修側欄；手機詳情為單頁、報修底部短表單。
- 搜尋、狀態、負責人緊鄰結果，作用中條件可見、可逐個／全部清除，與 URL 同步。
- 儀表板先看目前專案的反覆故障與分類；保留工具與資產、舊測試紀錄唯讀入口。
- 新流程無計時、完成時間輸入、逐站設定；舊紀錄不刪除。外部通知暫不串接。
- 工作目錄依使用者要求維持目前 checkout；不重試建立 worktree、不使用子代理。
