# 公司供應商聯絡資料

在「料號申請 → 待處理料」，點「信件生成」旁的「供應商聯絡資料」。公司有效帳號共用查詢、複製；只有管理員能新增、修改及匯入。既有個人聯絡簿仍屬個人帳號，不會轉成共用資料。

## 查詢與修改

- 搜尋涵蓋公司、英文別名、代理品牌、姓名、Email、電話及原始欄位。來源條件與搜尋顯示於結果上方，可個別清除或全部清除。
- 點公司名稱開啟詳情，可逐欄或一次複製完整資料。「來源與原始欄位」保留檔案、工作表、列號與未辨識欄位；同名欄位不互相覆寫。
- 管理員在詳情按「修改」，或按「新增聯絡人」。Email 可空白；填入時必須有效。未填 Email 的窗口仍可查詢，不能自動成為收件人。

## 更新 Excel

1. 按「匯入與比較」，一次選取多份 XLSX、XLS 或 CSV。每份最多 5 MiB，合計 15 MiB、50 張工作表、20000 列；單張最多 10000 列／256 欄。
2. 更新檔請選擇原本的「來源群組」，不要因新版檔名改變而另建群組。新資料來源才使用新群組。
3. 核對表頭列與欄位對應。可展開每張工作表，調整對應或略過。未辨識的欄位仍保留原值；無法辨識的整張工作表會明示略過。
4. 差異分為新增、變更、人工修改衝突、對應不明、未變更、本次缺少。變更顯示目前值與匯入值。只勾選要儲存的列；衝突預設不勾選，明確選取才覆蓋衝突欄位。對應不明須手動選既有窗口或另存新聯絡人。
5. 按「套用已選」一次儲存。未勾選、本次缺少的紀錄不刪除；新版沒有對應的欄位不清空。來源未變更的人工修改也保留。

比對使用來源群組、公司／明列別名、Email 或姓名，必要時以明列品牌、分類、工作表與窗口類別縮小候選。無法唯一辨識時不猜測。合併儲存格只展開實際合併範圍；同列業務與主管分開保存。中英文姓名依固定順序組合，與欄位順序無關。代理商欄明寫 N/A／NA 且已有原廠 Brand 時，以明列原廠顯示公司，原標記仍保留於來源。

原始欄位的值或格式變更也列為差異，可展開前後值核對；不因欄位尚未對應而默默略過更新。完全相同的重複來源列只做未變更配對，不寫入，避免再次匯入時新增副本。

## Gemini 支援檢查

選用「Gemini 支援檢查」，使用 API 管理已設定且未過期的 Google Gemini 模型。可以只核對表頭，或勾選最多 100 筆差異；對應不明的紀錄也可交由檢查。送出前會列出資料範圍，需勾選同意傳給 Google。只接受 Google 官方 API 位址，不把本次同意套用至其他代理服務。

只傳表頭、工作表資訊及勾選列的變更前後／候選資料，不上傳整份原檔。結果是建議，不會自動對應欄位、修改聯絡資料或寄信。沿用既有 AI 用量紀錄與請求逾時處理。實際公司資料不納入測試檔或 Git。

## 信件生成

公司名稱、明列英文別名及代理品牌採精確匹配，並合併使用者私人聯絡簿中該廠商的設定，Email 去重。每封信可展開匹配窗口勾選，並直接修改收件人、副本與主旨。無精確匹配時明示，由使用者填寫；不以模糊相似字串猜收件人。匯出 HTML 延續固定表格寬度與長位號換行，只複製內容，不代為寄送。

## 儲存與驗證

公司表 `workspace.company_supplier_contacts` 與私人表分開。RLS 依目前有效公司帳號授予讀取，管理員授予寫入；匿名及非公司帳號無法讀取。批次 RPC `apply_company_supplier_contacts` 檢查目前帳號、角色及逐筆版本；任一衝突會回滾整批。手動更新同樣保留匯入基準，供下次比較人工修改。
