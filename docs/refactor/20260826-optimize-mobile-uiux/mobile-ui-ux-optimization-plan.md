# 手機版網站 UI/UX 優化說明

## 1. 文件目的

本文件記錄此 branch 已完成的 **Mobile UI/UX demo 更新**，供維護者與 agent 評估是否採納至正式產品。內容不涵蓋 Desktop／Mobile component 分離、responsive 判斷或資料夾配置等架構重構。

可操作的本地 demo 位於 `docs/refactor/20260826-optimize-mobile-uiux/mobile-ui-demo/index.html`。目前變更只作用於 demo，沒有把 UI/UX 功能寫入正式 `src`、串接 API 或外部網站；Desktop demo 沿用既有元件與 CSS，Mobile 才呈現本文件所述調整。

## 2. 此 branch 已完成的 Mobile UI/UX 更新

### 全站導覽與頁面資訊

- 專案資訊與主要專案操作集中於頁首，功能模組改用可展開的切換區，底部保留固定工作區導覽。
- Test Tracker 增加整體完成率、機台總數與各狀態數量，讓使用者進入頁面後先掌握工作概況。
- 手機內容使用 `100dvh`、safe-area、獨立內容捲動與小螢幕重排；互動目標以至少 44×44px 為原則，並支援 `prefers-reduced-motion`。

### 篩選與機台清單

- 篩選列固定在結果區上方，順序為「搜尋 → 站點 → 狀態 → 工程師」，排序維持次要層級。
- 作用中條件以可個別移除的 chip 顯示，支援全部清除，並同步至 URL query parameters。
- 空結果使用固定文字 `目前篩選條件沒有符合的機台`，同時保留清除條件入口。
- 機台改以適合窄螢幕閱讀的卡片呈現；保留機台、目前／下一站、工程師、狀態、進度與阻擋問題等決策資訊。
- 每張卡片提供明確的全寬「更新進度」主操作，次要功能不再與進度條共用隱含點擊行為。

### 測試進度流程

- 更新進度使用全螢幕 Sheet，header、站點選擇、狀態摘要與儲存狀態在操作過程中保持清楚。
- 待處理測項優先排列，已完成測項預設收合；一次只展開一個測項，降低長頁面的重複控制量。
- 測項提供「開始」、「完成」、「回報異常」、進度、備註與時間資訊；有未解問題時禁止直接完成。
- 變更後顯示尚未儲存數量與固定儲存操作；關閉、切換站點或離開頁面前提供防止遺失資料的處理。
- 「完成此站」會先顯示影響筆數；存在未解問題時顯示阻擋原因，不直接批次完成。

### Quick Issue

- 從測項開啟精簡的異常回報 Sheet，自動帶入機台、站點與測項上下文。
- 第一層只保留問題描述、優先級、照片／附件與送出操作，負責人放入「更多設定」。
- 手機附件輸入支援相機或檔案選擇，並顯示檔名、大小與移除操作。
- 必填錯誤使用 inline message；未送出的問題描述在 demo session 內保留，成功後回到原測項並顯示關聯問題。

### 測試時間校正與時區

- 「開始／完成」可記錄操作當下時間，另提供「校正時間」供事後補登實際開始與結束時間。
- 日期與時間分開使用手機原生輸入，支援「套用現在時間」、即時耗時預覽、跨日計算與錯誤區間阻擋。
- 輸入者只選 GMT offset，不選國家；支援常見整點、半小時與 15／45 分鐘時差。
- 輸入值依所選 GMT 解析為同一絕對時間；切換 GMT 時保留該時間點並轉換欄位顯示，不會改變已計算的耗時。
- 儲存後開始與結束時間固定以台灣時間（GMT+8）顯示。demo 的「現在時間」使用 `Date.now()`；正式產品應優先採可信任的 server timestamp。

更完整的 Test Tracker 行為與採納要求見 `test-tracker-mobile-workflow-optimization.md`。

## 3. 此 demo 未代表已完成的正式功能

- demo 資料只存在瀏覽器記憶體，重新載入後會重置，沒有呼叫正式 API 或寫入資料庫。
- 儲存、建立問題、附件上傳與站點切換為互動模擬；權限、網路失敗、多人同步及部分成功仍需正式實作。
- demo 已展示 URL 篩選行為，但正式頁面仍需與既有 router、query schema 及 deep link 規則整合。
- 時間校正尚未正式寫回 `started_at`、`completed_at`、`actual_hours`；時區解析、validation 與耗時計算應在產品程式碼中落到可共用且可測試的功能。
- 此 branch 沒有宣告完成真機、螢幕閱讀器或完整瀏覽器矩陣驗證。

## 4. 正式採納原則

1. 以 demo 驗證過的 Mobile workflow 為參考，不要求 Desktop 跟著改版，也不得複製 API、state、validation 或計算邏輯。
2. 先抽出可共用的問題建立、附件、時間解析、時區換算、耗時計算與 mutation 狀態，再接上 Mobile UI。
3. 保留既有 RWD：Mobile UI 本身仍需適應 320、375、390、430px、橫向畫面、軟鍵盤與 safe-area，不能只支援單一手機寬度。
4. 篩選清單持續遵守 `AGENTS.md` 的位置、欄位順序、chip、URL、空結果與行動版可見性契約。
5. 正式 PR 應分階段導入並附上元件測試、核心 workflow E2E 與關鍵 viewport 視覺回歸；若產品規則與 demo 不同，以正式 domain rule 為準。

## 5. 建議採納順序

1. Mobile shell、44×44px 觸控目標、`dvh`／safe-area 與篩選契約。
2. 機台卡片主 CTA、進度 Sheet、測項排序／收合與未儲存防呆。
3. 單項儲存狀態、「完成此站」確認與錯誤／部分失敗處理。
4. Quick Issue 與共用問題建立、附件流程。
5. 時間校正、GMT 輸入、台灣時間顯示與 server timestamp。
6. 320–430px、200% zoom、鍵盤、VoiceOver／TalkBack、離線及網路失敗驗證。
