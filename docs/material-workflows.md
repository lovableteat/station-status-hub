# 料件工作流程與下載

更新：2026-10-28。沿用黑底青綠與共用 Dialog、Button、Tabs；設計參考依 `ui-ux-design-references.md` 選用，不另安裝 UI 框架。

## 檔案一鍵下載

- 單一檔案保留原格式；多檔或資料夾下載為一個 ZIP，保留目錄與空資料夾，不再要求存取整個下載資料夾。
- 支援串流寫入的瀏覽器先選 ZIP 儲存位置，再逐檔寫入、顯示進度。取消或來源失敗會中止寫入，不顯示成功。
- 使用 classic ZIP，單批含結構須小於 4 GiB、少於 65,535 個項目。無串流儲存能力時，ZIP 暫存上限 128 MiB；超過時提示改用支援的 Chrome／Edge 或分批。此限制不改變單檔上傳的 1 GiB 契約。

## 料件資料與狀態追蹤

- 表格與待處理料的「狀態／更新」皆開啟同一筆料件、同一個視窗；內含料件資料與狀態追蹤兩個頁籤。
- 共用一次儲存，連同欄位、單號／網址、狀態、備註與圖片提交。切換頁籤保留草稿，讀圖中禁止儲存。
- 新增追蹤內容必須選狀態；只有單號／網址變更不強制新增歷程。既有匯入追蹤與歷程保留。
- 儲存使用開啟編輯時的版本作 CAS。其他人先更新時，不覆蓋新資料；錯誤保留目前草稿。
- 位號為 `ME` 的料件標示「ME 製作・免申請」，保留主料、替代料、原料號與追蹤歷程，不列入待處理申請數量、清單或廠商申請信件。只依實際 ME 位號判斷，不由料名猜測，也不把 ME1 或混合電性位號視為免申請。
- 待處理清單在桌面使用固定 56px 列高；分類與合併的狀態／追蹤更新控制項皆為 36px。窄螢幕換行並保留觸控高度，狀態與更新兩區始終等高。
- 主料與替代列表格的虛擬料號為無框複製控制；有值點擊即複製原值，空值顯示「未提供」，不啟動編輯、確認或寫入。修改仍在料件資料視窗，沿用原有權限與儲存流程。
- 狀態追蹤分成「目前狀態」、「本次新增紀錄」及「歷史紀錄」。歷史由新到舊，列出狀態、更新時間、更新人及申請資訊；新增追蹤用青綠、處理中用黃色、已完成用綠色，並保留文字標籤。未知歷史狀態保留原文，不推定完成；草稿在儲存前不改變目前狀態。
- 待處理料每列可點星號，並以「特別標記」分類查看；依位號群組標記，同組替代廠商共用。沿用既有本機標記，依 BOM 保存在目前瀏覽器，不寫入公司共用資料，也不提供跨裝置同步。搜尋、分類與替代廠商條件均顯示可移除標籤，「全部清除」不刪除星號標記。

## 信件生成

- 開頭與簽名在同一編輯區；保留一個 `{{料件清單}}`，匯出時在該處插入各廠商的料件表格。標記遺失／重複時阻止匯出，不丟棄文字。
- 預設主旨為 `[{廠商}][VERA_GPU][料號申請][蒐集]`，可修改整體格式或逐封主旨。`{廠商}` 替換廠商名稱，`{BOM}` 可替換目前 BOM 名稱。
- 新版第一次使用會串接舊開頭與簽名；舊儲存值保留。編輯內容與主旨格式記在本機瀏覽器。
- 匯出直接擷取當下編輯 DOM；中文輸入法選字與圖片讀取中先等待，避免 React 狀態尚未更新造成漏字。非同步圖片限原編輯工作階段，關閉後不插入其他視窗。
- 公司供應商聯絡資料依名稱、明列別名／代理品牌匹配，統一大小寫、標點與 Inc.／Co., Ltd.／Corporation 等公司尾綴；不猜測地區、技術名稱或相似品牌。請核對收件人，可修改或逐一勾選；未匹配者可在聯絡資料補上明確公司別名。只產生 HTML、複製內容，不自動寄信。

## RLC 專案替代料優先順序

- 入口位於料號申請頁首「RLC 優先順序」。在視窗上方直接選擇這份 BOM 所屬專案並按「套用專案」；BOM 管理也可修改相同歸屬。規則屬於該 BOM 的專案，而非頁面上無關的專案。
- 僅 R／L／C 與 PR／PL／PC 位號納入，電感包含 `LB48`、`PLB48`，支援 `C354_C0P1`、`LB48_C0P1` 等板別後綴與同類位號範圍；依完整 Name、封裝、額定值等原文分組，保留單位大小寫，避免把 `10m` 與 `10M` 合併。不同描述不模糊合併，需人工核對。
- 候選料以廠商＋MPN 識別，跨同專案 BOM 可沿用規則。實體／虛擬料號保持原值，不自動代填或改寫來源 BOM。
- 客戶承認、AVL、工程確認都需「已通過」或「不適用／免承認」，且無來源禁用／不建議限制，才有推薦資格。供料欄 Approved 不代表專案承認。
- 資格皆預設待確認。合格後依正整數優先序，數字小者優先；未排序或第一名同名次不任意挑選。未出現在目前 BOM 的既存候選保留規則並排除推薦。
- 搜尋、狀態、類型篩選緊接表格上方，顯示可移除條件；空結果保留表頭。每列的「設定廠商順序」會進入專屬設定頁，廠商表單不再放在整張規格表格下方。返回清單保留條件與未儲存草稿。
- 在廠商設定頁點各家「設定／修改」，填客戶承認、AVL、工程確認與順位，再按「儲存此廠商設定」。`1` 表示優先使用，`2` 是第一替代，`3` 是第二替代；尚未確認的資格維持待確認。
- 例如同一種 0402／100Ω／1% 電阻有多家廠商：先確認本專案允許使用哪些料號，再把合格廠商排為 1、2、3。來源位號只是電路板上使用這種規格的位置，完整位號在設定頁底部展開；它不代表優先序。
- 資料表 `workspace.rlc_priority_rules`；RLS 對應既有物料工作區讀取／編輯權限，明確 workspace 設定優先於 legacy page 權限。未登入、停用帳號、無權限不能讀寫；管理員可編輯。
- 伺服器驗證操作者、專案、識別碼、狀態與排序，寫入操作者與時間；以時間戳 CAS 防止過期覆蓋。重新載入後可用「還原最新規則」丟棄單一草稿，避免默默覆蓋。

驗證：`tests/vendorMailTemplate.test.mjs`、`tests/VendorMailEditor.test.mjs`、RLC／Tracking 同目錄測試、`tests/test-plan/zip-download*`。實際資料庫權限與 CAS 用 `tests/sql/rlc-priority-rollback-probe.sql` 驗證，整個交易回滾。

## 顯示欄位與官方 Non PVL 匯出（2026-10-29）

- 在「欄位」旁按「匯出顯示欄位」下載 Excel，只含目前可見欄位並維持欄位順序。資料範圍是目前搜尋、篩選、排序後的全部廠商明細，不受當前分頁限制；狀態追蹤欄匯出文字，空白虛擬料號不借用實體料號。原完整報表入口保留。
- 顯示欄位 Excel 依欄位設定寬度、固定表頭與列高上限，同一主料的廠商明細使用相同底色，保留篩選。Ref Des 在欄內換行但不無限撐高整列，完整位號與長文字仍留在儲存格及註解，可點選儲存格查看或複製，不刪減來源。
- 「狀態追蹤／更新」欄包含最新已儲存的狀態、進度說明、申請資訊、更新人與時間；沒有紀錄顯示「未追蹤」。完整報表同樣使用最新紀錄，不把空白狀態當成「新增追蹤」。草稿須先儲存才會匯出，舊匯出檔不會自動更新。
- PLM 申請檔依使用者提供的官方 `applyNonPvlParts.xls`：Excel 97–2003 BIFF8、`Sheet1`、A1 逐字為「料號(必填)」、A 欄寬 29.5 字元，下一列起每列一個文字料號，無篩選、隱藏欄與額外工作表。官方來源含 208 筆既有資料，只作格式核對，不隨程式封裝或代填。
- 不建議料視窗可逐筆取消勾選，或搜尋後按「排除搜尋結果」。同一實體料號的重複明細共用勾選狀態，匯出時去重；沒有實體料號的列不可匯出。
- PLM 紅字退件訊息整段貼上後按「比對退件料號」，檢視精確匹配與未匹配結果，再按「排除已匹配的 N 個料號」重新下載。未知料號不排除，不判定 PLM 是否實際核准；只排除使用者指定的退件料。
- 排除只影響目前 BOM 視窗工作階段的申請檔，不刪除 BOM、原檔或追蹤紀錄。「全部選取」可復原，切換 BOM 後重新選取；完整明細匯出仍保留所有原資料。
