## 修正

- 背景更新先讀 RLS 篩選的輕量版本清單，再分批取變動紀錄；未變更物件重用，撤權／刪除紀錄移除，改名即使內容版本不變仍更新。
- 同範圍背景更新不重疊；被新請求或送出取代的批次停止。送出期間暫停背景輪詢，舊讀取結果不能覆蓋已確認的提交。
- trigger 改用 composite row 比對，保留 null 行為與未來新增欄位檢查。權限、私人主管評分、版本衝突規則均保留。
- 新版客戶端要求 compact receipt：資料庫提交成功後回傳 request ID、版本、狀態和實際已存內容的 SHA-256；客戶端核對再更新畫面。舊版客戶端仍可使用完整回應。重試冪等性與退回通知交易保留。
- 從 Realtime publication 移除未使用的考核來源，避免大附件再經即時處理。考核與通知仍由原本 API／通知訂閱更新。
