# 檔案資料夾返回紀錄修正

原因：資料夾變更只呼叫 replaceState，沒有建立資料夾的瀏覽器紀錄；瀏覽器上一頁因此直接回到先前工作區，且元件沒有還原瀏覽器返回後的資料夾。

修正：使用既有共用 history helper 建立空間／資料夾紀錄，路徑列返回與前進共用瀏覽器紀錄。共用 watcher 只有在導覽守門通過後才發送還原事件，避免上傳／刪除進行中仍切換資料夾。子資料夾連結初次開啟補上父層紀錄，重新整理不重複建立；根目錄仍可返回原工作區，不攔截正常離開。

保留 project、搜尋與格式等 URL 條件及既有 history state；不改檔案內容、Storage 或權限。只讀隔離資料目視確認：進入兩層、瀏覽器返回到父層、前進回子層、重新整理後返回，以及切換人員後返回原空間與資料夾。

回歸測試先證明舊版只有 2 筆紀錄而非預期 4 筆，再驗證一般導覽、子資料夾連結與重新整理、上傳阻擋／前進紀錄、router metadata 保留及根目錄正常離開。

驗證結果：252 項檔案工作區測試通過；新增的 3 項回歸含 router metadata 與根目錄離開檢查亦通過。TypeScript、ESLint 與 production build 通過。實際瀏覽器對隔離假資料操作返回、前進、重新整理、直接子層連結與切換人員還原皆通過；未操作正式登入後的公司資料。
