# Material workflows and RLC implementation plan

使用者已授權整批實作、驗證、提交與部署，不再要求階段確認。沿用既有黑底青綠、共用元件、持久搜尋／篩選與 CE 契約。實際公司資料不進 Git 或外部設計工具。

**Goal:** 修好多檔下載、合併料件更新與追蹤、保留完整信件編輯內容，並建立專案限定的 RLC 替代料資格與優先順序。

**Architecture:** 三個獨立領域並行，主流程整合由主代理處理。下載使用既有串流 sink 寫出單一 ZIP；料件與追蹤共用同一草稿與一次儲存；信件改為單一內容範本與可編輯主旨格式；RLC 專案規則獨立持久化且以資格篩選後才推薦。

**Tech stack:** React、TypeScript、既有 shadcn 元件、Supabase、既有檔案傳輸 sink；不新增套件。

- [ ] 下載：追查 `showDirectoryPicker` 的受保護目錄拒絕；多檔改單一 ZIP，保留檔名／階層，驗證取消、同名、錯誤與大檔限制。維持單檔 1 GiB 串流。
- [ ] 信件：單一編輯器含可移動的 `{{料件清單}}` 插入位置，舊開頭／簽名合併遷移；修正重開視窗、中文組字、貼圖非同步與匯出快照造成的文字遺失。主旨格式預設 `[{廠商}][VERA_GPU][料號申請][蒐集]`，整體格式與逐封主旨都可改。
- [ ] 料件：更新與追蹤都進同一個 Dialog；共享基本資料與追蹤草稿，一次儲存包含所有輸入，保留歷史、圖片、單號、連結及版本衝突。移除待處理料「定位」，合併「追蹤／更新料號」入口。
- [ ] RLC：只處理 R/L/C（含 PR/PL/PC），依完整規格文字與種類分組，不由單一電值推論相容。規則以 BOM 指定的專案為準；未指定專案不可建立全域排序。客戶認證、AVL、工程驗證各預設待確認；三者皆符合／明示不適用且無禁用來源才可參與正整數排名；首位同分不任選。保留未出現在目前 BOM 的同專案規則，不修改原 BOM 或虛實料號。
- [ ] 驗證：各領域測試先紅後綠，驗證專案隔離、角色權限、並行版本及原始資料不變；瀏覽器桌面／390px 目視、實際信件 HTML／ZIP 內容、型別檢查、ESLint、build，最後正式部署與資料驗證。

UI 參考使用專案 `docs/ui-ux-design-references.md`、TypeUI 的元件一致性與表單層級，以及 Impeccable product 指引。所有外站內容只作參考。
