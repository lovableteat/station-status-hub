# 績效退回狀態高亮設計

日期：2026-09-21

## 目標

讓員工、課長與部長不必逐字閱讀，就能辨識退回內容與歷史紀錄；同時保留文字標籤，避免只靠顏色傳達狀態。

## 範圍

統一高亮三種既有畫面：

1. 員工看到的主管逐項退回回應。
2. 員工及主管看到的逐項退回紀錄。
3. 課長及部長看到的部長退回歷程。

不修改資料格式、送退件流程、附件功能或頁面排版。

## 視覺規則

- 退回狀態沿用現有績效系統的玫紅語意色。
- 使用深玫紅表面底色、完整的 1px 玫紅邊框與高對比文字，不使用側邊色條。
- 當前逐項退回回應顯示「主管逐項退回回應」；歷史摘要保留「退回」文字。
- 部長歷程只高亮 `return` 事件；`approve` 事件維持目前中性／確認樣式。
- 高亮套用於整個狀態區塊，而非只改標題文字；附件仍位於同一區塊內。
- 手機與桌面使用相同語意，不增加新欄位或額外操作。

## 實作方式

- 在 `AssessmentEntryFeedback.tsx` 對已退回的唯讀逐項回應及退回歷史加上明確狀態 class／attribute。
- 在 `PerformanceSectionReports.tsx` 對歷程事件標記 `return`／`approve` action。
- 在 `performance.css` 定義共用退回色；`performance-bright.css` 只在現有亮化主題需要時補足覆寫。
- 優先沿用既有元件與資料，不新增元件、套件或新的狀態來源。

## 驗證

- 元件回歸測試確認 return 與 approve 產生不同狀態標記。
- 執行相關績效測試、ESLint、production build 與 `git diff --check`。
- 實際檢查桌面與手機：退回項目明顯、文字可讀、核准項目沒有誤套退回色。
