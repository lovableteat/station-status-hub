# 機台維修資料查詢來源設計

## 目標

讓「資料查詢空間」可以把「機台維修紀錄中心」的正式資料當成即時知識來源。使用者提問時，系統先從有權限的維修專案中找出最相關的機台、站點、測項進度、問題及工具資產，再只把這些片段交給既有 AI Provider 產生答案。答案下方固定顯示可點擊來源，讓使用者回到原始專案與資料位置核對。

## 範圍

### 納入的維修資料

- 專案摘要與目前狀態
- 機台基本資料與機台代碼
- 測試流程、站點與站點內容
- 各機台在各站點的測項完成／未完成進度
- 問題追蹤紀錄、嚴重度、狀態與處理資訊
- 專案已配置的工具、程式碼與指令資產

本階段不把 Test_Plan 上傳檔案內容當成檢索來源；避免把檔案解析、OCR 與維修正式資料混在同一階段。

## 查詢範圍

- 開啟資料查詢空間時，若目前已有維修專案，預設勾選該專案。
- 使用者可以勾選多個專案，也可以一鍵選取全部可用專案。
- 使用者明確調整過選取範圍後，不因頁面中的目前專案變更而覆蓋其多選結果。
- 不允許查詢未選取或不存在的專案；後端會再次驗證專案 ID。

## 權限與安全

- 檢索 RPC 必須要求有效 Supabase Auth session。
- 後端以 `current_system_user_id()` 對應系統帳號，並確認帳號已啟用且已核准。
- 使用者必須同時擁有「資料查詢空間」與「機台維修紀錄中心」的檢視或管理權限。
- 管理員與超級管理員仍經由同一個檢查入口取得存取權。
- 權限檢查必須在 `security definer` RPC 內執行，不能倚賴前端隱藏按鈕，也不能倚賴既有較寬鬆的維修表 RLS。
- RPC 只回傳回答所需的知識欄位，不回傳密碼、API 金鑰或其他機密欄位。

## 即時知識片段

採用查詢時計算的 SQL CTE／UNION，而不是手動同步或 Embedding 索引。每次提問都直接讀正式表，因此資料更新後立即可查，沒有額外 Embedding 費用，也沒有同步延遲。

每個片段至少包含：

- 穩定片段 ID
- 來源類型與來源資料 ID
- 專案 ID 與專案名稱
- 標題、內容摘要、更新時間
- 返回原始頁面的模組與路由參數
- 綜合相關度分數

## 排序策略

中文全文切詞在 PostgreSQL 內不適合作為唯一依據，因此採混合排序：

1. 機台代碼、名稱及問題編號的完全相符。
2. 前綴與大小寫無關的包含比對。
3. 將查詢拆成空白／常見標點分隔的詞，計算命中數。
4. `pg_trgm` 對標題與內容做中英文模糊相似度。
5. 對機台、問題及測項進度提供適度來源權重，並以更新時間作小幅加權。

後端最多回傳 20 筆，前端預設取 16 筆；避免把整個資料庫塞進 AI 上下文。

## AI 上下文與答案

- 使用者可見的訊息維持原文，不插入檢索內容。
- 檢索片段以一次性、不可見的 system context 加入該次 Provider request，不寫入使用者訊息。
- 每段以 `[M1]`、`[M2]` 編號，系統提示要求維修事實只能依據片段回答並在句尾標示來源。
- 若檢索失敗，停止 Provider request 並顯示可重試錯誤，不能靜默改成無來源回答。
- 若查無資料，直接建立本地助理訊息說明沒有符合的維修證據，避免無必要的 Provider 費用及幻覺。
- 無論模型是否正確輸出 `[M#]`，答案下方都顯示本次實際使用的來源卡片。

## 引用跳轉

所有來源連結都包含 `workspace=station-status`、`project=<uuid>` 及目的模組：

- 專案摘要：系統儀表板
- 機台與進度：L10 測試追蹤，附 `system` 與站點參數
- 站點／流程：L10 流程設定，附站點參數
- 問題：問題追蹤，附 `openIssue`
- 工具、程式碼、指令：工具與資產，附資產檢視參數

來源卡使用真正的連結，支援新分頁開啟；點擊後由現有工作區路由切到對應專案及資料。

## UI

- 在資料查詢空間的對話區新增精簡「資料來源」區塊。
- 「機台維修紀錄中心」來源預設啟用，旁邊顯示已選專案數。
- 專案選擇器提供「目前專案」、「全部選取」、「清除」與逐項勾選。
- 查詢完成後顯示實際找到的來源數；答案下方依序顯示來源類型、標題、專案、摘要及跳轉按鈕。
- 顏色、密度與現有資料查詢空間一致，不另做一套視覺語言。

## 驗證

- SQL 契約測試：權限、專案篩選、六類來源、查詢與數量限制、排序與路由參數。
- TypeScript 單元測試：預設／多選／全選狀態、上下文編號、來源 URL、對話引用序列化。
- 元件契約測試：來源選擇器、錯誤與空結果、答案來源卡固定顯示。
- 相關既有 API chat 與權限測試、正式 build。
- 套用 migration 後用真實登入 session 執行 RPC，並在本機瀏覽器實測單一專案、多專案、精確機台、問題查詢及引用跳轉。
