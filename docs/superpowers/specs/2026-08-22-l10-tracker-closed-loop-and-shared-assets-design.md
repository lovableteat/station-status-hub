# L10 追蹤、問題閉環、儀表板導覽與通用資產設計

日期：2026-08-22

## 目標

本次調整把四個互相關聯的工作流一次收斂：

1. L10 測試追蹤的排序、固定篩選列、卡片檢視與空結果狀態。
2. 測試項目與問題追蹤之間的資料閉環及 `Blocked` 呈現。
3. 儀表板導覽時，以可見、可清除的條件自動篩選目標頁面。
4. 工具與資產的通用／工作區專用範圍。

## 一、L10 測試追蹤

### 固定篩選列

搜尋、工程師、站點、狀態與排序固定顯示在資料區上方，不藏在 Popover。專案管理、批次重置、匯出與 PDF 保留在次要操作區，避免篩選與具破壞性的專案操作混在一起。

篩選條件以同一列 chip 顯示，包含由儀表板帶入的自動篩選。每個條件可以個別移除，也可一次清除。桌面與行動版使用相同語意與欄位順序。

### 排序

提供下列排序：

- 機台 ID 由小到大（預設）。
- 機台 ID 由大到小。
- 建立時間由新到舊。
- 建立時間由舊到新。

排序同時套用於表格與卡片檢視，並以資料列 ID 作穩定排序的最後判斷。

### 卡片檢視

每台符合條件的機台必須且只能出現在一個 lane。lane 依序包含「待開始」、實際流程站點、「已完成」，只有資料存在站點不匹配時才新增「未對應站點」。卡片顯示機台 ID、序號、工程師、目前狀態與進度，避免只依 `current_station` 完全相等而遺失資料。

### 空結果

桌面表格即使沒有符合結果仍保留 header，tbody 顯示「目前篩選條件沒有符合的機台」。行動版顯示同文案空狀態。

### 規範與稽核

在根目錄 `AGENTS.md` 寫入固定篩選列規範，並在文件中記錄其他工作區的差異：資料清單頁應統一；畫布、圖層、模型等非資料清單控制可保留領域特有介面；高密度行動版的次要排序或工具可收合，但目前作用中的條件必須保持可見。

## 二、問題追蹤閉環

### 關聯來源

沿用 `issues.project_id`、`system_id`、`station_id`、`test_item_id`，不新增重複的關聯表。相同測試項目可關聯多個問題。

### 資料庫規則

在 `workspace` schema 新增 migration：

- 問題新增或改成未解決狀態時，將對應 `test_progress` 建立或更新為 `Error`。
- `open`、`in_progress` 視為未解決；`resolved`、`closed` 視為已解除阻擋。
- 問題解除後不自動將測項標記為完成，測項維持異常紀錄，等待人員確認。
- 新增原子 RPC 供完成測項使用。只要相同專案、機台、站點與測項仍有未解決問題，RPC 拒絕完成並回傳可辨識錯誤。
- 函式使用固定空 `search_path`、完整 schema 名稱、必要的複合索引，並限制授權至應用程式需要的角色。

### 前端呈現

測試項目顯示關聯問題摘要、問題狀態及前往問題追蹤入口。任一關聯問題未解決時：

- 測試項目呈現紅色異常狀態。
- 額外顯示 `Blocked`。
- 站點摘要顯示完成數與 Blocked 數，完成百分比仍只計算 `Done`，不把阻擋項目偽裝成完成。
- 手動儲存完成、結束計時並完成、整站完成三條路徑都必須走相同守門規則。
- 被拒絕時顯示「尚有問題未被解決」。

問題新增後即重新載入關聯問題與進度；問題狀態透過正確的 `workspace` realtime schema 同步。

## 三、儀表板導覽與自動篩選

### URL 是單一來源

跨頁篩選使用 URL query parameters，不使用易遺失的全域暫存或 `sessionStorage`。目標頁讀取參數後把它同步至固定篩選列；條件在重新整理、返回與分享連結後仍可重現。

### 站點產能與瓶頸

點擊任一 station 卡片時前往 L10 測試追蹤，帶入 station ID 並排除已完成機台。固定篩選列顯示「站點：…」及「排除：已完成」。

### 需關注機台

區塊主按鈕改為「開啟生產監控牆」，帶入 `attention` 篩選。需關注條件沿用儀表板資料定義，涵蓋低完成率、異常／Blocked 以及其他現有優先關注條件。生產監控牆顯示「需關注機台」自動條件 chip。

個別「查看機台」改前往 L10 測試追蹤，帶入該機台 ID，只顯示對應機台資料。

儀表板 KPI 與站點統計永遠以完整專案資料計算，導覽條件只影響目標頁顯示，不回寫或污染儀表板統計。

## 四、工具與資產通用化

### 範圍模型

「工作區」指平台工作區，例如機台維修、料號申請、Data Center 與 PCB Designer，不等同維修專案。

工具、上傳檔案、程式碼與指令增加：

- `scope = global`：所有工作區可見、可用、可管理。
- `scope = workspace`：只在 `owner_workspace` 對應的工作區可見。

使用 check constraint 保證 global 資料沒有 owner、workspace 資料一定有 owner。現有資料依既有公司共用庫語意 migration 為 global。新增項目預設為目前工作區專用，使用者可明確開啟「通用」選項。

scope 控制可見範圍；既有專案 assignment 控制某項資產是否套用至目前維修專案，兩者互不取代。

### 管理與篩選

新增／編輯介面提供通用選項。編輯通用項目時提示修改會影響所有工作區；若只需局部客製，應複製為工作區專用項目。

固定篩選列提供「全部」、「通用工具」、「目前工作區專用」。查詢只載入 global 與目前工作區資料，並對 `(scope, owner_workspace)` 建立索引。維修知識搜尋函式同步遵守相同可見範圍。
