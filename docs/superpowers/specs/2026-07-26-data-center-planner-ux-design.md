# Data Center 2D 規劃體驗改造設計

## 目標

依序改善 Data Center 規劃工作的四個問題：

1. 廠房尺寸取消固定上限，輸入與調整可正常完成。
2. 冷熱通道不再要求使用者先理解 X/Z 座標。
3. 電力佈線提供手動、指定設備自動與全自動三種可用流程。
4. 2D 畫布分為配置、冷卻、電力三種工作模式，避免所有圖示與線路同時競爭注意力。

四項功能共用既有 `FacilityPlan` 與 `RackPlan`，2D 與 3D 仍顯示同一份資料。不得建立第二套 Data Center，不得偷偷移動使用者的設備，也不得破壞既有模型上傳、機櫃配置與本機持久化資料。

## 已核准的產品決策

- 廠房寬度與深度不設固定上限，只接受有限正數，最小值為 1 公尺。
- 廠房縮小後若機櫃、通道或 PDU 超出邊界，保留原座標並顯示警告，不自動搬動。
- 冷熱通道新增時可選「自動配置」或「自由配置」。
- 電力佈線同時提供：
  - 手動逐點畫線。
  - 選擇 PDU 與機櫃後自動產生直角路徑。
  - 依距離、容量與負載自動分配。
- 2D 畫布提供「配置／冷卻／電力」三種工作模式，只突出目前工作內容，其餘內容淡化或隱藏。
- 依 1 → 4 的順序完成；每項都必須獨立測試、比對最新 `origin/main`、非強制推送到 `main`，並確認 GitHub Pages 部署成功。

## 方案比較

### A. 只修表單

只移除 80 公尺上限並改善欄位文案。改動小，但通道座標、佈線與畫布雜亂完全沒有解決。

### B. 全自動規劃

尺寸、通道與電力都由系統自動安排。操作最簡單，但無法處理現場特殊走線、既有設備位置與人工修正。

### C. 混合式視覺規劃（採用）

用視覺操作處理日常工作，保留進階座標與手動路徑以支援特殊現場。自動規劃產生可編輯結果，而不是鎖死配置。

## 1. 廠房尺寸

### 輸入行為

- 尺寸欄位使用獨立字串草稿，允許使用者暫時清空、選取並重新輸入，不在每個鍵盤事件時把空字串強制轉為最小值。
- 按 Enter、離開欄位或點擊「套用尺寸」時才提交。
- 合法值必須：
  - 可轉為有限數字。
  - 大於或等於 1。
  - 四捨五入至 0.1 公尺。
- 不設定 HTML `max`，增加按鈕也沒有固定上限。
- 非法輸入保留在欄位中並顯示就地錯誤，不修改已儲存尺寸。
- 顯示地板面積、目前比例與「自動符合畫布」狀態。

### 超界警告

- 尺寸提交後檢查所有機櫃 footprint、冷熱通道旋轉後 footprint 與 PDU 位置。
- 超界物件不移動。
- 尺寸區顯示警告摘要，例如「3 個物件超出新邊界」。
- 2D 畫布以紅色外框與警告徽章標示超界物件。
- 警告清單可點擊並選取對應物件。
- 3D 場景仍保留原座標，避免資料在不同視圖間不一致。

## 2. 冷熱通道

### 新增流程

點擊「新增冷通道」或「新增熱通道」後先選擇：

- **自動配置**
  - 選擇橫向或直向。
  - 選擇全部機櫃或指定機櫃列。
  - 系統依所選機櫃的外接範圍產生通道，兩端保留 1 公尺餘量。
  - 冷通道預設寬 2.1 公尺，熱通道預設寬 1.15 公尺。
  - 若沒有可用機櫃，退回地板中央的安全預設尺寸並顯示說明。
- **自由配置**
  - 在地板中央新增通道。
  - 使用者直接拖曳通道。
  - 選取後顯示端點／角落縮放把手與 90° 旋轉控制。
  - 拖曳與縮放以 0.25 公尺吸附網格。

### 位置表達

- 主要介面顯示「距左側／距上側／長度／寬度／方向」，不要求理解中心點 X/Z。
- 精確 X、Z、角度保留在可展開的「進階座標」區。
- 選取通道後，畫布與側邊檢查器同步顯示尺寸與方向。
- 通道超界時保留資料並顯示警告。

## 3. 電力佈線

### 資料模型

`FacilityPlan` 增加 `powerRoutes`；既有 `powerFeeds` 保留並補充容量。

```ts
export type PowerRouteMode = "manual" | "assisted" | "automatic";

export interface FacilityPoint {
  x: number;
  z: number;
}

export interface PowerRoutePlan {
  id: string;
  feedId: string;
  rackId: string;
  mode: PowerRouteMode;
  points: FacilityPoint[];
  enabled: boolean;
}

export interface PowerFeedPlan {
  id: string;
  label: string;
  x: number;
  z: number;
  color: string;
  enabled: boolean;
  capacityKw: number;
}
```

### 舊資料相容

- 讀取沒有 `powerRoutes` 或 `capacityKw` 的本機舊資料時自動補值。
- PDU 預設容量為 120 kW。
- 先依 `RackPlan.powerFeed` 與 PDU label 的正規化名稱配對。
- 無法配對時選擇最近且仍有容量的啟用 PDU。
- 只補缺少的路徑，不覆蓋使用者已編輯的路徑。

### 三種操作

#### 手動逐點

1. 選擇起點 PDU。
2. 在畫布依序點擊建立節點。
3. 點擊目標機櫃完成。
4. Enter 完成、Esc 取消、Backspace 移除上一節點。
5. 完成後仍可拖曳中繼節點。

#### 指定設備自動

1. 選擇一個 PDU。
2. 多選一或多座機櫃。
3. 產生避開機櫃 footprint 的直角路徑。
4. 產生後可拖曳節點微調。

#### 全自動分配

- 只使用已啟用 PDU。
- 依剩餘容量、機櫃 `powerKw` 與曼哈頓距離排序。
- 優先避免超過 `capacityKw`；無法避免時仍建立路徑並標為超載。
- 使用者確認預覽後才套用，不在背景偷偷重排。

### 電力可讀性

- PDU 卡片顯示容量、已分配 kW、使用率、機櫃數與超載狀態。
- 路徑預設採直角折線，不再從每個 PDU 直接連到所有機櫃。
- 選取 PDU 時只突出該 PDU 與所屬路徑；選取機櫃時只突出其供電路徑。
- 路徑可停用、重新指派與刪除。

## 4. 2D 畫布工作模式

### 配置模式

- 機櫃為主要物件。
- 顯示機櫃代號、狀態與選取外框。
- 模型名稱只在選取時顯示。
- 通道降低透明度；PDU 使用小型定位標記；電力路徑隱藏。

### 冷卻模式

- 冷熱通道為主要物件，顯示拖曳、縮放與旋轉把手。
- 機櫃使用中性 footprint 供對齊參考。
- PDU 與電力路徑隱藏。
- 顯示通道類型圖例與超界警告。

### 電力模式

- PDU、路徑與路由節點為主要物件。
- 機櫃簡化為供電端點；通道隱藏。
- 顯示手動／指定設備自動／全自動工具。
- 顯示容量圖例、未供電機櫃與超載警告。

### 共用整理規則

- 頂部只保留模式切換與該模式相關的主要動作。
- 選取物件的詳細資料放在固定檢查器，不用大型底部浮層遮住畫布。
- 標籤依縮放層級顯示；低縮放只顯示代號，高縮放才顯示次要資訊。
- 未選取物件不使用強烈發光；健康狀態以小型角標呈現。
- 超界、超載、未供電等警告有一致圖示、顏色與可點擊清單。

## 元件與檔案邊界

- `facilityPlan.mjs`
  - 尺寸驗證、面積、旋轉 footprint、超界檢查。
- `facilityAisles.mjs`
  - 自動通道生成、友善位置轉換、拖曳／縮放正規化。
- `powerRouting.mjs`
  - 舊資料補值、負載計算、PDU 配對、直角路徑與自動分配。
- `FacilityPlannerDialog.tsx`
  - 尺寸、通道與 PDU 設定表單。
- `DataCenter2DPlanner.tsx`
  - 三模式畫布、選取、拖曳、縮放、路由節點與警告視覺。
- `DeploymentPlanningCenter.tsx`
  - 擁有共享狀態、持久化、2D/3D 串接與對話框協調；不承擔純演算法。

## 錯誤處理

- 尺寸、PDU 容量與通道尺寸錯誤使用欄位就地訊息。
- 自動配置沒有選取目標時不建立資料並顯示明確提示。
- 手動畫線離開模式或切換廠區時取消未完成草稿。
- 全自動分配先預覽；沒有啟用 PDU 時禁止套用。
- localStorage 舊資料格式錯誤時保留可解析欄位，其餘回退安全預設，不清空整個廠區。
- 唯讀使用者可切換模式與檢視，但所有修改、路由與套用按鈕停用。

## 測試與驗收

### 自動測試

- 尺寸沒有固定上限、空白草稿可輸入、非法值不提交。
- 縮小地板後超界物件保持原座標且被列出。
- 自動與自由通道都可建立；縮放、旋轉與友善位置轉換正確。
- 舊 `powerFeeds` 資料可補齊容量與路徑。
- 三種路由模式皆產生有效、可編輯且與 PDU／機櫃關聯的路徑。
- 容量不足時產生超載警告，不靜默捨棄機櫃。
- 三種畫布模式只顯示對應主要圖層。
- 2D 修改仍同步至 3D 使用的相同資料。

### 瀏覽器驗收

- 寬度輸入 120、500 與 1250.5 均可套用；輸入空白、Infinity、0、負值會被拒絕。
- 縮小地板後，超界機櫃／通道／PDU 不移動且可由警告選取。
- 自動與自由新增各建立一條冷通道與熱通道。
- 自由通道可拖曳、拉伸與旋轉，無需輸入 X/Z。
- 手動建立一條含至少兩個轉折點的 PDU 路徑。
- 指定 PDU 對多台機櫃自動佈線成功，節點可微調。
- 全自動分配有預覽、容量摘要與超載警告。
- 配置／冷卻／電力模式切換後，畫布沒有同時堆疊不相關圖示。
- 重新整理後尺寸、通道、PDU 與路徑仍存在。

## 發布流程

每一項功能完成時：

1. 執行對應測試、全部 Data Center 測試、指定 ESLint 與 production build。
2. `git fetch origin main`。
3. 若遠端有新提交，先 rebase 到最新 `origin/main` 並重跑驗證。
4. 建立單一功能提交。
5. 使用非強制 `git push origin HEAD:main`。
6. 確認遠端 SHA 與本機一致。
7. 等待 GitHub Pages workflow 完成且 conclusion 為 success。
