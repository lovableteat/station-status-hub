# Station Capacity Flow Design

## Goal

站點增加後，仍能從第一站到最後一站一眼讀出順序、每站負載與瓶頸，不再因卡片網格換行造成閱讀順序混亂。

## Considered Approaches

1. **保留多欄網格只調整欄數**：改動小，但站點一多仍會換行，第二列的第一張容易被誤認為下一欄，因此不採用。
2. **單一垂直清單**：順序明確，但大量佔用儀表板高度，不適合桌面橫向空間，因此不採用。
3. **橫向流程軌道**：依 `station_order` 排列編號卡片，以連接線和箭頭表達流程；桌面橫向捲動、行動裝置 scroll snap。此方案最符合「第一站到最後一站」需求，為採用方案。

## Design

- 計算層繼續以 `station_order` 穩定排序，並把 `stationOrder` 暴露給呈現層與測試。
- 區塊標頭顯示「第 1 站 → 最後一站」、站點總數、目前瓶頸與總剩餘工時。
- 卡片改為固定最小寬度的橫向流程軌道；每張卡片頂部顯示 `第 N 站`、站名與到下一站的方向連接。
- 瓶頸站保留琥珀色，但增加「瓶頸」標籤與明確外框；一般站、已清空站使用不同但克制的狀態。
- 卡片只保留主要數據：總機台、完成、處理中、剩餘工時與進度。完整計算公式繼續放在 hover/focus 詳情。
- 容器提供可見的左右捲動提示、鍵盤操作與 scroll snap；不依賴 hover 才能理解順序。
- 點擊卡片仍導向對應測試站點，不改變既有資料或導航參數。

## Error Handling and Compatibility

- 沒有站點時顯示明確空狀態，不產生空捲動容器。
- 相同 `station_order` 時以站名作穩定次排序，避免重新渲染時跳動。
- 桌面、平板與手機都只使用一條流程線，不因斷點重排成不明確網格。

## Verification

- 擴充 dashboard metric 測試，確認亂序輸入仍依 `station_order` 輸出。
- 新增 UI 契約測試，確認流程軌道、連接線、站別標籤與橫向捲動存在。
- 使用 1、6、12 個站點做桌面與行動尺寸檢查。
- 執行 dashboard 測試、ESLint 與 production build。
