# 部門完整考核資料查看

部門績效總覽新增「部門所有人填寫資料」。部長可查看目前組織樹中直屬課長、各課同仁及直屬／代理課同仁；課長仍只能查看自己所屬課的同仁。包含本期已儲存的草稿、填寫中／退回、待審核及已完成資料，沒有已儲存考核的人員也保留在名單中。

清單支援姓名、帳號、部門、課別、主管搜尋及考核狀態篩選，條件保存在 URL，個別與全部清除皆保留工作區導覽。完整內容以唯讀方式在本頁展開，可直接選取複製；包含 IDP、OKR、KPI 實績、自評、佐證附件與連結、主管分數、逐項回覆、整體回饋、工作指示及既有退回歷史。沿用共用 ReviewDetail，避免與原考核紀錄產生不同的顯示規則。

各課已完成成績表也提供「查看實績／STAR」，直接定位到該同仁的完整自評與主管審核回覆。此入口會清除人員清單的搜尋／狀態條件，避免內容被隱藏；被查看的考核 ID 保存於 URL，重新整理仍可開啟同一筆。顯示的是同仁實際填寫的內容，不另生成或改寫 STAR。

## 部門考核匯出

部門績效總覽頁首及人員清單標題皆提供「匯出資料」，在頁內展開格式與人員勾選，不需切換到主管評分頁。開啟時勾選目前篩選範圍內已儲存且已解鎖的人員，可取消個別勾選、全選或清空。篩選移除的人員不會被匯出；未儲存／未解鎖的勾選項目停用。

Excel 每人一張工作表，HTML 依人員分段，沿用既有匯出格式：包含完整 IDP／OKR／KPI 原文、自評與主管分數、逐項／類別評語、整體回覆、工作指示、佐證連結與附件檔名；附件本體及退回歷史不嵌入檔案。僅點選匯出時透過受控部門詳情 RPC 讀取，最多同時兩筆，不使用只允許直屬主管的資料表入口。任一讀取失敗不產生部分檔案；鎖定、週期／存取名單變更、元件卸載，或 Excel 建立期間權限狀態改變都會阻止下載。

匯出補強驗證：12 項渲染與匯出測試、App 型別檢查、正式建置通過。以實際元件和模擬資料操作頁首入口，勾選一人下載 Excel 後讀回確認單一工作表、STAR 原文、主管回覆、指示及成績；手機篩選已完成後 HTML 僅含兩人。390px 手機頁面沒有水平溢出，匯出按鈕高度 44px；桌面與手機無瀏覽器錯誤。未下載正式人員的考核檔案。

## 權限與讀取成本

- 兩個專用讀取 RPC 各自檢查有效系統帳號、考核工作區存取、績效主管資格及當下組織關係。原有考核資料表及直接主管的寫入政策未變更。
- 既有資料保護密碼、目前階層與留存的紀錄保護範圍仍需解鎖。鎖定資料不傳送考核 ID、狀態、日期、分數或完整內容。詳情 RPC 每次重查資格，手動猜 ID 無法取得其他部門資料。
- 清單僅傳人員與狀態等中繼資料，不含大型附件與原始回覆。點選某位同仁時才載入該筆完整內容；切換人員、週期、篩選或鎖定後，延遲回應不能重新顯示先前資料。
- 紀錄依本期、同仁身分選最新一筆，兼容 UUID 與舊帳號身分，顯示名稱以目前帳號資料為準。

## 驗證

- 隔離 PostgreSQL / PGlite 執行實際遷移與 RPC：所有狀態、課長與代理課納入、同仁姓名、同身分最新版、跨部門及不同週期拒絕、群組密碼、組織調整後撤權、停用帳號及匿名呼叫均驗證。
- React 渲染測試驗證按需讀取、篩選隱藏詳情、鎖定後遲到回應無法重新顯示內容、空表頭保留、從成績表查看正確的 STAR 紀錄，以及原始實績和主管整體回覆／工作指示完整呈現；既有成績、進度及 API 額度測試同時通過（8 項）。
- App 與 Node 型別檢查、正式建置通過。實際元件配模擬資料於桌機、平板及 390px 手機檢查；手機頁面寬度 390px，表格內水平捲動，頁內詳情可讀，無新增瀏覽器錯誤。
- 正式資料庫已套用遷移。確認匿名角色無執行權、內部權限 helper 不向 authenticated 開放。未建立或更改任何正式考核紀錄。
- 正式部長群組設有密碼，驗證時沒有有效的部長解鎖授權；以未解鎖的部長身分讀取確實遭拒。完整資料的成功讀取在隔離資料庫驗證，未繞過正式群組密碼。
- Supabase advisor 新增兩項「authenticated 可執行 SECURITY DEFINER」提醒；此為需要依組織關係執行受控唯讀查詢的兩個 API，已檢查函式內授權、固定 search_path、撤銷匿名權限及拒絕案例。沒有新增匿名可呼叫或 RLS 關閉問題。[Advisor 說明](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)。其他既有資料庫提醒未在本次修改。
