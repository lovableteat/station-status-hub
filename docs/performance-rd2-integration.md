# RD2 績效與當責操作整合

功能來源：[company_web](https://liu52417.github.io/company_web/)，原始碼 [liu52417/company_web](https://github.com/liu52417/company_web)，核對版本 `a3ed8771d9749106eed29103efc2d194bcd44f09`（2026-08-31）。

本次移植的是評核操作，不是 GitHub 提交活動。移除前一版的 GitHub 活動卡、快取資料與讀取程式；其餘工作區不變。

## 操作對照

| 原站操作                     | 整合後                                                                                              |
| ---------------------------- | --------------------------------------------------------------------------------------------------- |
| 職級政策、KPI/OKR/IDP 權重   | 「系統說明與政策」，四種職級；原站將 13、19 列於同一 Junior 選項，本頁沿用該分組                    |
| EE/FW 團隊與職級選擇         | 八組 Base line / Outstanding 標準直接對應原碼                                                       |
| 員工姓名、工號、STAR 自評    | IDP、OKR、KPI 分項填寫；送出須完成三項                                                              |
| 證明圖片、內部連結           | JPG/PNG/WebP 壓縮預覽、移除、下載；每項最多兩張，合計約 1.5 MB 編碼文字上限；HTTPS 連結可加入／移除 |
| 自動暫存、手動草稿、清除草稿 | 依登入帳號／週期／模式／紀錄隔離的本機草稿；清除須確認，不清空其他 localStorage                     |
| 送出自評                     | 工作區確認寫入後才改狀態、顯示成功；失敗保留草稿                                                    |
| 主管當責評分                 | 保留原碼實際存在的兩道 Commitment 題目，均為必填 1–5 分；僅主管可進入，且只列出考核人設定為自己的直屬同仁 |
| 深淺模式                     | 限定績效工作區，記住選擇，不修改平台其他工作區樣式                                                  |

保留現有平台的考核週期、目標分類／權重／進度、主管文字回饋、選填綜合 0–100 分、退回補充、紀錄搜尋／篩選與 CSV 匯出。沒有替原站創造額外當責題目，也沒有以兩題評分自動推算績效總分。

## 儲存與安全界線

- 沿用既有 `workspace.performance_reviews` 及原有登入、RLS、績效管理權限，不新增資料表；`20260901120000_scope_performance_reviews_to_managers.sql` 會把讀寫範圍收斂為員工自己的紀錄、指定主管的直屬紀錄，管理員則可檢視全部。檢視權限可閱讀自己的紀錄與暫存本機草稿；正式寫入遵守現有績效編輯權限。
- 一般員工不會看到「主管評分（主管專用）」分頁、主管當責分數、主管回饋或綜合評分；即使手動改網址，也會回到員工自評畫面。
- 結構化自評存於 `self_feedback`，格式 `RD2_SELF_V1\n` + JSON；主管內容存於 `manager_feedback`，格式 `RD2_MANAGER_V1\n` + JSON。舊版純文字仍顯示並保留；主管更新不改自評與原有 goals。
- 證明圖片隨自評存在既有受權限保護的紀錄內。沒有複製原站的圖床金鑰或 Google Apps Script 網址，也不會把人事資料送到原站外部服務。
- 圖片只接受點陣格式；顯示文字不使用 HTML 注入；CSV 對公式字首跳脫，匯出實績／評分／連結，不輸出 JSON 或 Base64 圖片。
- 更新以 `updated_at` 比對避免覆寫並行修改；舊草稿若來源版本落後，先阻止寫入並提示核對。新增紀錄使用固定草稿 ID；回應遺失重試時只接受相同內容，避免重複建立或覆寫他人修改。
- 正式模式不再以示範種子冒充雲端資料。舊共用本機快取檔未刪除，讀取失敗時可回退顯示非原始示範列；正式雲端回傳（包含空結果）仍為主。
- 本次未取得／搬移原站外部試算表的人事紀錄；整合的是網頁功能和評核標準。
