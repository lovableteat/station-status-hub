# RD2 績效、組織與評分標準

2026-09-03 更新。評分標準以使用者提供的 `RD2_HW2_KPI-OKR_IDP_example.xlsx` 為準，取代先前從 company_web 移植的簡化標準。來源格位、差異及部署步驟見 [部署說明](performance-organization-rollout.md)。

## 操作與資料

- IDP／OKR／KPI 各自提供輸入框與實績清單；新增後顯示在下方，可連續加入、編輯、刪除。儲存／送出一併收入尚未按新增的文字，舊單段實績完整成為第一筆。
- 員工工號、HW／FW、職務角色、數字職等分開填寫。組織層級由管理員設定，自評的角色／職等不會改變管理權限。
- 數字職等 19／23 的 KPI／OKR／IDP 權重為 60／20／20；29／33 為 50／30／20；39／43 為 40／35／25。13／49 原表未提供權重，標示待確認，不填入預設值。
- 主管依受評者組織層級評分：部長對應高階管理層（原題號 1–7）、課長對應中階管理層（8–14）、一般成員對應一般員工（15–21）。各類須完成七題，使用原表五級評分描述。
- 舊版兩題維持原題號，不移成一般員工前兩題；新評分記錄題庫版本與受評類別。主管更新完整保留原自評與目標，員工更新保留主管內容。舊紀錄缺工號不阻擋主管評核。
- 當責 1–5 分與選填綜合 0–100 分分開保存，原表沒有換算公式。CSV 包含職等、分項實績及原題號評分；員工匯出不含主管欄位。
- 證明圖片／HTTPS 連結仍隨類別保存，沿用每類兩張圖片及既有容量限制。

## 組織與保護

- 組織架構僅績效主管與網站管理員可見，帳號來自全站，只有管理員能修改。部長 → 課長 → 一般成員，一個部可含多個課；部長看所屬各課、課長看課內成員。
- 更換上級時同步部／課名稱，禁止循環、跳級及有下屬時直接降級。舊主管需明確指定部長／課長，不自動猜測。
- 只更動績效組織與績效權限，保留全站角色、其他工作區與頁面權限。員工更改網址也無法進入主管／組織操作，資料庫 RLS 再次驗證存取。
- 主管可設定群組密碼；網站管理員及上級主管也需密碼才能看受保護考核。解鎖不擴大組織範圍，員工仍可填自己的自評。
- 變更／移除密碼只允許原設定者且須驗證舊密碼，沒有網站管理員重設入口。移動員工或整個課保留歷史保護，不能以重編組織繞過密碼。
- 密碼獨立使用 bcrypt（cost 10），不沿用網站舊登入雜湊。解鎖限本次登入、30 分鐘，錯五次暫停五分鐘；密碼與解鎖狀態不寫瀏覽器儲存。
- 雲端考核不使用共用離線快取。主管草稿只留目前畫面，鎖定、到期或無法確認權限時清除；員工自評草稿仍依帳號／週期／紀錄隔離。

這是網站帳號層級的存取保護，非端對端加密；資料庫管理權／service-role 仍具資料庫層級權限。密碼持有人離職前需自行解除或交接密碼，網站管理員無法繞過。

## 儲存與驗證

自評沿用 `RD2_SELF_V1\n` JSON，主管沿用 `RD2_MANAGER_V1\n` JSON；舊純文字保留，新增欄位向後相容。更新比對 `updated_at`，回讀成功才回報已儲存；新增重試固定 ID，只接受相同內容或資料庫指定的主管名稱。

- 實績／標準／序列化測試 20 項通過；真實 PostgreSQL（PGlite）執行新 migrations、RLS、pgcrypto，40 項通過，無正式人事資料。
- 加上既有績效測試共 28 項，27 通過；既有 CSS 不得含固定色碼測試在基準版本即失敗。
- 績效元件 ESLint、正式建置通過。完整 TypeScript 檢查有其他模組既有錯誤，本次績效元件未報錯。
- 瀏覽器本機驗證：管理員改組織／繼承課別、主管唯讀、員工入口隔離、空結果表頭、錯誤及正確密碼、鎖定後移除內容、實績新增／編輯／重開、職等權重、一般員工七題送出與回讀。

正式資料庫與登入驗收須依部署說明完成。GitHub Pages 發布不會自動執行 SQL。
